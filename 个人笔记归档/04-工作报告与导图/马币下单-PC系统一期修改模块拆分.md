## 1. 总体口径

本期目标是在不改变 PC 既有 USD 结算主口径的前提下，为马来西亚 PC 下单链路增加 MYR/RM 展示、选择、订单快照和后续展示能力。

核心原则：
- 结算币种仍为 USD，返利扣减、财务结算、审批判断、底层主流程仍按 USD。
- MYR/RM 是前台展示币种和订单下单币种快照，不是本期新的财务结算币种。
- 下单前使用当前生效汇率；进入确认页后形成锁定口径；提交后订单生命周期内读取订单快照，不随新汇率重算。
- 汇率、国家配置、订单快照应以后端权威数据为准，前端只负责展示和交互。
- 国家未配置、配置停用、无有效汇率、缓存/数据库异常时，降级 USD-only，不阻塞原 USD 下单。

会议澄清补充：
- 汇率来源为 ERP 财务月度基准汇率，系统定时拉取。会议中提到每月 1 号 9 点查 ERP 汇率。
- 汇率波动在 3% 以内不频繁调整；超过阈值触发邮件通知和 7 天缓冲。
- 最终下单接口需要后端校验汇率/价格是否发生影响下单的变化；如波动导致前后端口径不一致，提示下单失败并返回编辑页重新刷新后再提交。
- 销售待下单/Pending Submission 场景沿用销售创建待下单时的价格和汇率快照，渠道确认期间不重新按当前汇率刷新。
- 审批侧不需要做币种切换，只要按订单下单时的币种、金额和汇率快照展示。

## 3. 模块与具体功能拆分

### 3.1 多币种配置管理

覆盖页面/入口：
- 建议入口：Admin 后台 -> 系统管理 -> 多币种配置。
- 会议中提到也可评估放在协同平台，最终入口由技术方案确定。

具体功能：
- 新增国家多币种配置。
- 配置国家/国家编码，新增后编辑不可改。
- 配置结算币种，固定 USD，只读。
- 配置展示币种和符号，例如 MYR/RM。
- 配置汇率数据源，本期默认财务月度基准汇率，预留实时 API、手动维护。
- 配置波动阈值，马来默认 3%，范围 0.1 到 50。
- 配置缓冲天数，默认 7，范围 1 到 30；会议中提到若配置 0 可理解为实时生效，需技术方案确认是否开放。
- 配置金额精度，默认 2，范围 0 到 4。
- 配置预警邮件接收人。
- 配置免责声明，中英文均必填，用于前台汇率横幅。
- 配置启停状态，启用前必须存在当前生效汇率，停用需要二次确认。
- 新增/编辑/启停/人工修正/通知人变更需要记录审计日志。

关键规则：
- 新增并启用后，只影响该国家新访问用户和新订单。
- 停用后，新页面隐藏 MYR，仅保留 USD；历史订单快照保留。
- 修改阈值只影响后续汇率同步判断。
- 修改缓冲天数只影响后续新产生的待生效汇率。
- 修改展示币种只影响新订单，历史订单继续按原订单币种展示。

### 3.2 汇率同步、阈值判断与邮件通知

覆盖范围：
- 定时汇率同步任务。
- 汇率持久化表和缓存。
- 待生效汇率状态。
- 业务邮件通知。
- 运维日志和告警。

具体功能：
- 定时拉取 ERP 财务月度基准汇率。
- 校验汇率有效性：非空、非 0、非负数、格式正确。
- 首次无当前生效汇率时，直接写入当前生效汇率。
- 计算偏差率：`|新汇率 - 当前生效汇率| / 当前生效汇率`。
- 偏差率小于等于阈值时，当前生效汇率不变，仅记录同步结果。
- 偏差率大于阈值时，新汇率进入待生效状态，预计生效时间为同步时间加缓冲天数。
- 待生效期间前台仍使用当前生效汇率，不向客户展示待生效汇率。
- 到期后自动切换为当前生效汇率，新订单使用新汇率，历史订单不变。
- 待生效期间如果又同步到新汇率且仍超过阈值，使用最新汇率覆盖待生效汇率并重新计算缓冲期。
- 待生效期间如果新汇率已回到阈值内，取消待生效汇率，当前生效汇率不变。
- 超过阈值时邮件通知销售/GTM/业务方，邮件包含当前汇率、新汇率、偏差率、阈值、预计生效日期和业务动作建议。
- 邮件失败重试 3 次，失败记录日志和告警，不阻塞汇率按期生效。

会议澄清补充：
- 会议中明确 3% 以内不频繁调整价格。
- 超过 3% 后给业务 7 天缓冲期，销售/GTM 可评估是否调整 USD 报价。
- 对短时间多次汇率变动，需要支持“最新待生效汇率覆盖旧待生效汇率”的处理，避免排队逐条生效造成混乱。

### 3.3 金额与币种公共能力

覆盖范围：
- 前端金额格式化工具。
- 汇率横幅组件。
- 币种切换状态。
- 后端金额/汇率/快照字段模型。

具体功能：
- 封装统一金额换算和格式化能力，避免各页面手写 `USD 金额 × 汇率`。
- 支持 USD/MYR 双币种展示，MYR 页面符号为 RM。
- 支持金额精度按国家配置处理。
- 支持汇率横幅展示当前生效汇率、生效日期、免责声明。
- 支持 Locked 状态横幅，展示订单锁定汇率、锁定日期、订单币种和免责声明。
- 支持 MYR/USD 切换，切换只影响展示，不改变库存、筛选、排序、价格校验和 USD 结算口径。
- 按渠道所属国家/合同国家判断币种配置，不按销售账号国家判断。
- 国家无配置、配置停用或无汇率时，隐藏 MYR 入口，降级 USD-only。
- 销售连续查看不同国家渠道时，币种上下文需要随当前渠道重置，不能沿用销售本人或上一个渠道的本地选择。

建议快照字段：
- `displayCurrency`：下单币种/展示币种，例如 MYR 或 USD。
- `displayCurrencySymbol`：展示符号，例如 RM。
- `settlementCurrency`：结算币种，本期为 USD。
- `exchangeRate`：锁定汇率。
- `reverseExchangeRate`：反向汇率，如 CES 或详情展示需要。
- `exchangeRateDate`：汇率日期。
- `exchangeRateSource`：汇率来源。
- `exchangeRateSnapshotId`：汇率快照 ID。
- `usdAmount`/`settlementAmount`：USD 主金额。
- `displayAmount`：订单展示金额。
- `rateLockedAt`：锁定时间。

### 3.4 产品列表/选品模块

覆盖页面：
- 产品列表页。
- 组合包/服务价格展示。
- 销售代客选择 Partner 场景。

具体功能：
- 新增汇率横幅，展示当前生效汇率、生效日期、免责声明、MYR/USD 切换入口。
- 产品单价、促销价、服务价、加购合计支持按当前展示币种格式化。
- 默认展示 MYR；如果用户已有本地选择且当前渠道支持该币种，可沿用上次选择。
- 币种切换只刷新金额展示，不触发产品重新查询。
- 币种切换不影响库存、配额、MOQ/MTU、产品筛选、价格校验和加购逻辑。
- 销售代客/选择 Partner 时，按被下单渠道所属国家判断是否启用 MYR。

### 3.5 购物车模块

覆盖页面/功能：
- 购物车列表。
- 服务项金额。
- 底部合计。
- 查看渠道购物车。
- 共享/分享购物车。
- 购物车导出。

具体功能：
- 商品单价、促销价、小计、服务金额、商品行合计接入当前展示币种。
- 购物车总额、已选商品合计、节省金额按当前展示币种刷新。
- 一级/二级服务价格和服务小计按当前展示币种展示，服务选择规则不变。
- 销售查看渠道购物车时，按被查看渠道所属国家/合同国家判断是否支持 MYR。
- 购物车阶段不锁定汇率，始终使用当前生效汇率展示。
- 购物车内容、数量、服务、优惠变化后，以 USD 结果为计算基础，再刷新 MYR 展示。
- 分享列表、收到的分享列表、分享明细和导入购物车后的金额按接收方或被查看渠道所属国家配置展示。
- 分享购物车不锁定价格、汇率、库存、返利、运费、税费和订单金额。
- 接收方点击 Add to Cart 或 Replace Cart 时，按接收方当前账号、国家、合同、库存、MOQ/MTU、服务可售性和当前生效汇率重新计算。
- 如果本期不支持服务项随分享传递，需要在分享弹窗和收到分享明细中提示“仅分享商品和数量，不包含已选服务项”。
- 购物车导出保留 USD 主金额，可增加 MYR 参考金额、当前生效汇率、汇率日期和展示币种。
- 购物车导出的 MYR 金额为参考金额，需要标识“参考汇率/非结算金额”。

会议澄清补充：
- 分享购物车前台实际不展示金额或金额影响较小，重点确认后台是否存在分享时带价格/锁价逻辑。
- 会议中倾向：分享购物车前端改动较少，只要点击添加购物车后进入购物车能按当前上下文展示正确币种金额即可。
- 查看渠道购物车属于较深链路，若实现成本高，可与业务确认是否一期必须完整支持。

### 3.6 订单结算页

覆盖页面：
- 订单结算页。
- 返利弹窗。
- 底部结算栏。

具体功能：
- 展示当前生效汇率横幅和免责声明，支持 MYR/USD 切换。
- 商品单价、服务单价、订单金额、支付金额、服务小计按当前展示币种展示。
- 商品总额、税费、运费、返利抵扣、现金折扣、节省金额、应付总额按当前展示币种展示。
- 返利弹窗中的最大可用返利、总可用返利、已选择返利、行内可用余额、行内使用金额增加 MYR 展示。
- 底部应付总额和节省金额随币种切换同步刷新。
- 物流、发货日期、电源线、付款方式、备注等既有表单不新增业务规则；这些操作导致 USD 金额变化时，同步刷新 MYR 展示。
- 进入订单确认页前，以当前选择币种和当前生效汇率形成待锁定金额口径。

关键规则：
- 结算页仍使用当前生效汇率，不锁定汇率。
- 返利余额、返利选择、返利校验、返利 30% 上限和实际扣减仍以 USD 为准。
- MYR 在返利模块只做展示换算。

### 3.7 订单确认页

覆盖页面：
- 订单确认页。

具体功能：
- 展示锁定汇率横幅，包括锁定汇率、生效日期、Locked 状态和免责声明。
- 展示用户进入确认页时选择的下单币种。
- 商品、服务、运费、税费、返利、现金折扣、应付总额均使用锁定汇率展示。
- 底部订单总额和节省金额使用同一锁定汇率展示。
- 从结算页进入确认页时，锁定本次订单的下单币种、汇率和汇率日期。
- 用户返回结算页修改后，再次进入确认页需按最新结算结果重新锁定。
- 确认页不新增物流、付款、返利等业务操作，只调整只读信息中的金额展示口径。

会议澄清补充：
- 确认页可以使用从上一屏带来的锁定金额做展示，但最终下单不能只依赖前端传参。
- 最终下单接口需要后端重新校验价格/汇率；如发现汇率或价格变化导致口径不一致，应提示下单失败，返回编辑页重新刷新并提交。
- 确认页锁定的原因之一是返利按整单 30% 限制，如果确认页金额随汇率波动，会影响返利上限和用户感知。
- 确认页中的服务、有价服务等也需要跟随币种展示。

### 3.8 提交订单与订单快照

覆盖范围：
- 提交订单接口。
- 订单保存。
- 提交成功页。

具体功能：
- 提交订单时保存下单币种、锁定汇率、汇率日期、订单金额展示口径。
- 保存 USD 主金额/结算参考金额，用于结算、返利扣减、审批判断和财务口径。
- 保存展示金额，用于订单列表、详情、审批、导出、CES 回显等场景。
- 成功页金额按本次下单币种展示；无 MYR 信息时按原 USD 展示。
- 订单提交后不因后续汇率同步或配置变更重算历史订单金额。
- 历史订单无快照时，不补算 MYR。

后端校验要求：
- 后端需要权威校验当前汇率快照是否仍可用于本次提交。
- 后端需要权威校验 USD 结算金额、返利上限和应付金额。
- 如果校验失败，返回明确错误，前端提示返回编辑页重新刷新。

### 3.9 销售待下单/Pending Submission

覆盖场景：
- 销售创建待下单。
- Pending Submission 列表。
- 渠道办理页。
- 渠道确认页。
- Handle Confirm。

具体功能：
- 销售创建待下单订单时形成金额口径，保存下单币种、锁定汇率和锁定金额。
- Pending Submission 列表展示订单锁定金额、下单币种和锁定汇率。
- 渠道办理页商品、服务、返利、底部总额使用销售创建待下单时形成的锁定汇率。
- 渠道确认页只读金额与办理页保持一致，展示下单币种和 Locked 状态。
- 渠道确认提单后，后续列表、详情和审批沿用本次确认后的订单币种和锁定汇率。
- 倒计时、日期调整、物流、付款、返利办理能力为既有流程，本期只改金额展示和订单币种留痕。

会议澄清补充：
- 销售待下单场景下，渠道确认期间即使当前价格/汇率变化，也不自动刷新历史价格和汇率。
- 该逻辑与现有价格缓存一致，销售下单那一刻已经锁定，渠道确认有效期约 7 天，过期后需重新下单。
- 渠道返回办理页修改信息后，如果 USD 计算结果变化，按原锁定汇率刷新 MYR 金额。

### 3.10 Search Order 列表

覆盖页面：
- 订单列表 - All。
- 订单列表 - Pending。
- 订单列表 - Closed。
- Pending Submission 入口。
- 列表导出。

具体功能：
- Order Amount 按订单记录的下单币种展示，MYR 订单显示 RM，非 MYR 订单维持原币种。
- Actual Payable 与 Order Amount 使用同一订单币种和锁定汇率。
- MYR 订单展示锁定汇率和 Locked 标识；USD 或历史无锁定汇率订单按原展示。
- 混合币种列表中需要能识别每笔订单币种。
- 列表金额不使用当前生效汇率重算。
- Pending 订单不随后续汇率变化自动刷新历史金额。
- Closed 订单保留原订单币种和锁定汇率展示。
- Re-order 创建新订单时按新订单当时配置和汇率确认，不复用 Closed 订单汇率。

筛选、排序、分页：
- 订单号、项目名、创建日期、状态、来源等筛选沿用现有逻辑。
- 金额区间筛选默认按 USD 主金额筛选，页面提示应明确为 USD Amount。
- 如需要快速定位 MYR 订单，可新增 Display Currency 筛选项，取值 All/USD/MYR。
- Order Amount、Actual Payable 等金额列排序统一按 USD 主金额排序。
- MYR 展示金额只作为行内展示，不参与本期排序计算。
- 币种切换只改变当前页展示，不改变筛选条件、排序字段、分页位置和导出查询参数。

导出：
- 导出沿用当前筛选条件、当前列表范围或所选行范围，按既有交互确定。
- 导出文件至少保留 USD 主金额。
- MYR 订单补充展示币种、锁定汇率、汇率日期/锁定时间、订单展示金额、应付展示金额。
- 历史订单无快照时，MYR 相关列为空或展示“无快照”，USD 主金额正常导出。
- 导出说明需标识 MYR 为参考展示金额，结算金额以 USD 主金额为准。

会议澄清补充：
- 订单列表仍需要 MYR/USD 切换，主要满足马来销售查看和沟通需求。
- 如果当前页返回的数据包含 MYR 订单，则展示币种切换；如果当前页没有 MYR/其他展示币种数据，则隐藏切换。
- “当前页”是重点，不是全量历史数据；分页返回当前页有 MYR 才展示。
- ECP 订单和 PC 订单可能混合展示，需要按后端返回的币种字段处理。

### 3.11 订单详情

覆盖页面：
- Search Order 订单详情。
- 合同/订单详情相关金额区。

具体功能：
- 详情页汇率横幅读取订单锁定汇率，展示 Locked 状态和下单币种。
- Payment 区域的 Order Amount、Payment Amount、Use Rebates 等金额按订单币种展示。
- Product Info 区域的产品单价、订单金额、支付金额、服务订单金额、服务支付金额按订单币种展示。
- 商品合计、支付合计使用订单锁定汇率。
- 订单状态流、基础信息、物流信息、审批记录等既有详情内容不改造，仅调整金额字段展示口径。
- 销售创建、渠道创建、渠道确认等不同来源订单均读取订单记录中的币种和汇率。
- 历史订单无锁定汇率时不补算 MYR，按原展示方式处理。

会议澄清补充：
- 详情页同列表一样，需要使用下单时保存的币种和汇率。
- 如果支持切换 USD/MYR，应基于订单快照展示，不使用当前汇率重新计算。
- 快照展示不能在详情页实时计算，否则可能产生尾差和争议。

### 3.12 审批与待办

覆盖页面/入口：
- PC 端订单审批页。
- 飞书/移动端审批。
- 后台待办列表。
- PC 后台抛单 CES 确认/审批页。

具体功能：
- PC 审批页订单金额、实际应付、返利抵扣、现金折扣按订单币种展示。
- 商品/服务明细中的商品单价、服务单价、订单金额、支付金额按订单币种展示。
- 审批页展示订单锁定汇率和 Locked 状态；无锁定信息订单按原口径展示。
- 审批人看到的金额必须与订单详情一致。
- 移动端审批订单金额按订单币种展示。
- 移动端可折叠展示汇率信息，但审批人必须能查看锁定汇率、下单币种和 Locked 状态。
- 后台待办列表金额列展示订单币种金额；MYR 订单显示 RM 和币种标识。
- 待办列表可展示 Locked 或在详情中展示锁定汇率。
- 待办排序、权限、消息提醒和审批入口保持现有机制。

会议澄清补充：
- 移动端审批模板本身不需要改，主要是后端传参改为订单下单币种和对应金额。
- PC 后台 CES 确认/审批页与移动端/后台待办类似，只需把下单时候的币种、金额、汇率传过去展示。
- 审批侧不需要币种切换。

### 3.13 CES/ECP/合同导出兼容

覆盖系统/链路：
- PC 抛单 CES。
- CES 合同详情/订单详情回传。
- CES 到 ERP 主流程。
- PO/合同导出。
- ECP 订单混合展示。

具体功能：
- PC 创建订单后，需要把下单币种、汇率、展示金额、USD 主金额等快照信息保存并按接口契约传给 CES。
- CES 回传给 PC 详情/列表的数据应能带回当时的币种、汇率和金额快照。
- PO/合同导出的币种应按当前合同/订单币种展示。
- ECP 订单和 PC 马币订单混合展示时，PC 根据后端返回币种字段和快照字段展示。
- CES 未适配时，订单币种信息可选，不影响 USD 主流程。

会议澄清补充：
- 会议中多次讨论 CES 是否接收 USD、MYR、汇率以及是否自行换算，核心风险是尾差和退换货/返利释放口径。
- 最终拆分建议：PC 侧必须保存 USD 主金额、MYR 展示金额和汇率快照；CES 使用哪些字段需要技术契约确认。
- 合同/PO 导出侧已具备当前币种导出能力，若 PC 给到马币，导出应展示马币。
- ECP 侧有现存马币流程，本期原则上不改 ECP 配置和免渠道确认流程。

待确认：
- PC -> CES 接口是否要求同时传 USD 主金额、MYR 展示金额、双向汇率、汇率日期。
- CES -> PC 回传详情时是否原样回传快照字段，还是只回传当前币种字段。
- 退换货、返利释放、订单修改是否会引用 CES 自身汇率；如会引用，需要禁止使用实时汇率重新换算历史订单。

### 3.14 导入与币种识别

覆盖范围：
- AI 导入。
- Excel/批量导入。
- 含金额的导入内容。

具体功能：
- 导入内容包含金额币种时，识别 USD/MYR/RM。
- 按本期币种规则做展示与确认。
- 识别失败时默认按 USD，并提示用户确认。
- 不静默按 MYR 处理。

### 3.15 兜底、审计与测试

兜底功能：
- 汇率同步失败：当前生效汇率不变，记录日志，连续失败触发运维告警。
- 缓存不可用：降级查数据库；仍失败则前台隐藏 MYR。
- 数据库不可用：不更新汇率，前台继续使用缓存；缓存也不可用则 USD-only。
- 邮件失败：重试 3 次，记录失败，不阻塞待生效汇率。
- 无国家配置：前台 USD-only。
- 配置停用：前台新页面 USD-only；历史订单快照保留。
- 订单无快照：不展示 MYR，不补算。
- CES 未适配：原抛单主流程不受影响。
- AI 识别币种失败：默认 USD 并提示用户确认。
- 返利 MYR 展示异常：隐藏 MYR 参考，不影响 USD 返利扣减。

审计功能：
- 配置新增、编辑、启停、汇率人工修正、通知人变更记录操作日志。
- 汇率同步结果、无效汇率、待生效覆盖、待生效取消、到期生效记录日志。
- 邮件发送和重试记录日志。
- 下单快照创建、提交校验失败、历史订单无快照降级记录关键日志。

测试重点：
- 马来用户默认 RM，可切换 USD，金额显示一致。
- 产品列表、购物车、结算页使用当前生效汇率。
- 确认页、订单提交后列表/详情/审批使用锁定汇率。
- 汇率变化后，未下单页面刷新为新汇率，历史订单不变。
- 最终下单接口发现汇率/价格变化时，提示失败并返回编辑页。
- 销售待下单在渠道确认期间不重新按当前汇率刷新。
- 返利余额、选择、校验、30% 上限和扣减仍按 USD。
- 订单列表切换币种不改变筛选、排序、分页和导出查询参数。
- 当前页无 MYR 订单时隐藏列表币种切换。
- CES、导出、分享购物车、AI 导入、Re-order、Pending Submission、Handle Confirm 不遗漏金额字段。

## 4. 一期建议优先级

P0 必须完成：
- 多币种配置和国家启用判断。
- 汇率同步、阈值、7 天缓冲、邮件通知。
- 公共金额/汇率快照模型。
- 产品列表、购物车、结算页、确认页、提交订单主链路。
- 订单快照保存和最终下单后端校验。
- Search Order 列表、订单详情、PC 审批、移动端审批、后台待办展示。
- Pending Submission 锁定口径。
- USD-only 降级和历史订单不补算。

P1 建议完成：
- 购物车分享导入后的币种展示校验。
- 购物车导出和订单列表导出补充 MYR 参考字段。
- CES 回传详情字段契约和 PO/合同导出兼容。
- 列表 Display Currency 筛选。
- AI/Excel 导入币种识别。

P2 可后续优化：
- 多国家更多展示币种扩展。
- 实时汇率 API 或手动汇率维护。
- 按 MYR 金额筛选/排序。
- 更完善的人员选择器替代手工邮箱配置。

## 5. 主要待确认项

1. 多币种配置最终入口放 Admin 后台还是协同平台。
2. 缓冲天数是否允许配置为 0，以及 0 是否代表实时生效。
3. PC -> CES、CES -> PC 的字段契约，尤其是否必须双向传 USD/MYR 金额和双向汇率。
4. CES 退换货、订单修改、返利释放是否存在自行用实时汇率换算的逻辑。
5. 查看渠道购物车和分享购物车是否一期必须完整覆盖多币种，或允许只保证导入后购物车展示正确。
6. 订单列表币种切换是否只按当前页数据展示；会议倾向是当前页有 MYR 才展示。
7. 订单导出和购物车导出是否都需要加免责声明行或表头说明。
8. AI/Excel 导入是否是一期开启范围，还是只做兼容兜底。
