# 测试点生成平台评估报告（剔除 UI 与 CES）

## 0. 管理摘要

- 同口径双边剔除后，人工侧为377个业务需求检查点，平台侧为171条业务叶子断言。
- 机器检索结果为99个高相似、141个中相似、137个无候选；加权候选估算45.0%，但人工抽查发现大量跨页面误配，不能把45.0%当作真实通过率。
- 已完成人工逐项复核的下单过程模块严格有效覆盖下限为29.7%；极端场景为0完整、3部分、1遗漏。
- 当前范围仍有13条直接错误平台叶子（7.6%）和多类无依据扩展，结论为 **C级——需整改，只适合作为测试设计草稿**。

## 1. 评估范围

对比对象：

- 人工基线：`PC马币下单项目-测试导图.mm`
- 平台产物：`mindmap-ai (1).mm`

本报告按要求剔除 UI 和 CES 相关测试点后重新计算，未直接沿用上一版数字。

本次按“直接剔除UI和CES”的含义处理；极端业务场景不属于UI/CES，仍保留4项参与业务覆盖评估。

### 剔除口径

- **UI测试**：只剔除纯视觉、布局、颜色、字体、静态控件文案，以及分页、选择器清空等通用组件行为。
- **仍保留为功能测试**：金额、币种、汇率、字段业务值、权限、表单校验、按钮业务结果、页面间状态传递、历史快照和计算规则。
- **字段边界说明**：仅验证字段、标签或切币入口“是否出现/位于左右哪侧”的叶子按UI剔除；同字段的取值、来源、计算、只读规则和切换后的业务结果继续保留。因此71项UI口径包含静态字段构成，但不删除字段业务规则。
- **CES测试**：人工基线中模块或完整路径明确包含CES的检查点均剔除，包括CES模块、两条以CES为终点的端到端长链路，以及PC中明确以CES前后状态为判断条件的检查点。
- 平台侧同步剔除正文明确验证CES的断言和`UI/UX通用`/纯UI断言，避免只有基线缩小、平台候选却不缩小导致覆盖率虚高；复合叶子只要正文明确包含CES即整条剔除，不拆出其中的业务片段，口径偏保守。

## 3. 覆盖率结论

### 3.1 自动检索漏斗（不是人工最终覆盖）

| 覆盖层级 | 数量 | 占377项比例 | 说明 |
|---|---:|---:|---|
| 机器高相似候选 | 99 | **26.3%** | 相似度≥0.50，仍可能跨页面、跨角色或规则相反 |
| 机器中相似候选 | 141 | **37.4%** | 相似度0.38～0.50，通常缺独立断言、字段、数据、计算值或时点 |
| 机器无候选 | 137 | **36.3%** | 没有找到达到阈值的平台内容，但仍可能存在组合式弱覆盖 |
| 机器主题召回 | 240 | **63.7%** | 高相似与中相似合计，只表示检索到相关文字 |

部分对应按0.5折算：

```text
机器加权候选率
=（99 + 0.5 × 141）÷ 377
= 45.0%
```

### 3.2 建议向领导汇报的口径

> **机器高相似召回率：26.3%（99/377）**  
> **机器加权覆盖候选上限：45.0%**  
> **机器主题召回率：63.7%（240/377）**  
> **真实业务覆盖率：当前不可直接证明；45.0%仅作为管理层机器估算，人工抽查显示其更可能偏高**

45.0%是将中相似候选按0.5折算的机器召回估算，不能直接叫最终通过率。人工上下文门禁抽查发现：99个高相似候选的当前最佳链接中至少39个页面或角色错位，141个中相似候选中至少44个错位；同时137个无候选中也存在少量由多条平台断言组合支撑的假阴性。因此不能简单相减得到另一个“精确率”，正式有效覆盖率仍需建立需求—用例追踪矩阵后逐项签字。

本表是原始相似度检索分布，不是模块真实覆盖率。方向上Admin多币种配置仍是平台相对最强领域，但Search Order和订单审批存在严重跨页面泄漏：列表/详情金额被产品、结算或移动审批页面命中，审批返利被结算页返利命中，因此45.2%和45.5%不得用于模块质量排名。人工评审仍将极端场景、Search Order细节、下单状态快照和审批角色矩阵列为薄弱领域。UI测试与CES链路不在本表评价范围内。

极端场景的人工语义修正为：0项完整、3项部分、1项遗漏，加权37.5%。机器表中的0/1/3存在两个假阴性：平台分别提到了跨产品/购物车切币，以及Pending锁定、渠道办理沿用锁定和历史订单不重算，但都缺少人工基线中的完整组合条件。

### 4.1 已完成人工逐项复核的模块

| 模块 | 检查点 | 完整 | 部分 | 纯遗漏 | 错误覆盖 | 完整率 | 加权有效覆盖 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 极端场景 | 4 | 0 | 3 | 1 | 0 | 0.0% | **37.5%** |
| PC / 下单过程 | 150 | 23 | 43 | 62 | 22 | 15.3% | **29.7%** |

下单过程的29.7%是执行级严格下限：按“完整=1、部分=0.5、错误/遗漏=0”折算。22项是受4类错误规则波及的人工需求检查点，不是22条独立平台错误叶；对应汇率数据源3项、免责声明11项、前台固定2位精度5项、确认页锁定时点/币种只读3项。原74个机器无候选中仍发现至少10项可由其他平台叶子部分支撑，因此29.7%也不能外推为全项目唯一真值。

典型机器误配包括：产品页“偏差率计算公式”被普通横幅展示命中；结算页“小计”被购物车合计命中；销售待下单确认页“订单金额”被“分享购物车不保存订单金额”反向命中。逐项证据中的最佳候选必须经过页面、角色、操作和预期四重门禁后才能计覆盖。

## 5. 平台产物的优点

- 能识别Admin币种配置、MYR/USD、汇率横幅、金额换算、订单锁定、Search Order和PC审批等主要业务域。
- 能补充接口越权、重复国家、非法汇率、缓存/数据库降级、事务副作用等风险场景。
- 部分边界测试包含明确输入，例如0.1～50、1～30和0～4；形式上比“验证边界值”更可执行。
- 对权限、数据库唯一性、失败不落库和历史快照有一定工程风险意识。

需要强调：测试点形式明确，不代表预期一定正确。例如平台把“越界自动钳制”写成“提交拦截”，属于可执行但错误的测试。

## 6. 剔除UI和CES后仍存在的错误点

原评审人工确认16条错误平台测试点；其中3条正文明确验证CES并随本次范围剔除，当前范围仍保留 **13条错误测试点（占171条的7.6%）**。这些错误点按业务规则归并后主要包括：

该错误率受CES裁剪粒度影响：本报告采用“正文含CES即整叶剔除”。若只删除CES子断言、保留3条混合叶中的PC锁定/提交规则，则平台池为174条，直接错误仍为16条，占9.2%。主报告坚持171条的整叶口径，9.2%仅作为敏感性说明。

| 优先级 | 错误规则 | 人工基线口径 | 风险 |
|---|---|---|---|
| P0 | 金额精度默认4 | 配置默认2，范围0～4 | 默认配置被判错 |
| P0 | 前台金额按配置精度展示 | 前台金额统一四舍五入保留2位 | 全链路金额预期错误 |
| P0 | Admin不含中英文免责声明 | 免责声明中英文必填，并参与后续页面/历史快照 | 放过字段缺失和快照污染 |
| P0 | 编辑国家可重新选择 | 编辑时国家、国家编码、结算币种只读 | 配置主体及唯一性风险 |
| P0 | 确认页允许切换币种 | 确认页继承上一页币种并只读 | 破坏订单锁定规则 |
| P0 | 确认页仅作参考、提交成功才锁定 | 进入确认页即锁定；刷新保持不变，返回上一页再进入才更新 | 汇率锁定时点整体判错 |
| P1 | 波动阈值低于下界时拦截提交 | 低于0.1时钳制为0.1；高于50的行为平台遗漏 | 已生成部分与需求相反，另一侧缺失 |

| P1 | 审计不要求字段前后值 | 需记录操作人、时间、修改前后值 | 审计验证缩水 |
| P1 | 数据源项口径不完整且前后不一致 | 应展示3个业务名称，其中2项可见但不可选 | 技术枚举与业务口径混淆 |

平台测试点中出现“PRD-代码差异”“目标规则”等标签，却仍把代码现状或模型推断写成确定预期，说明平台缺少需求来源优先级和冲突门禁。

13条是“直接错误平台叶子断言数”，可复现编号为AI#9、#14、#15、#17、#18、#20、#23、#32、#57、#62、#63、#161、#165。另有AI#40“记住上次币种”属于无需求依据的扩展，应标待确认，但不计入直接错误。错误叶不能直接从99或141中机械相减：平台一条复合断言可能映射多个人工检查点，反之一个人工检查点也可能由多条平台断言共同支撑。因此45.0%只是未扣除错误和跨页面误配影响的机器候选估算。

其他需单列为“无依据扩展/待确认”的内容包括购物车导出不含MYR、新增导出免责声明等基线未明确要求的规则。T1流程中显式填写“金额精度=4”属于0～4范围内的合法测试数据，不等于宣称默认值为4，故不计入错误叶。

## 7. 主要遗漏与欠缺

### 7.1 极端场景

人工复核为3项部分覆盖、1项遗漏，具体如下：

- 后台MYR汇率为空时，平台只验证前台退化为USD-only，未完成“可正常下单”的端到端断言，判部分；
- 产品列表进入购物车并反复切币，平台分别有产品/购物车/结算切币描述，但缺跨页同一数据集的金额、符号和状态一致性，判部分；
- 销售下单后后台汇率变化，平台分别覆盖Pending锁定、渠道办理沿用锁定和历史订单不重算，但缺“7天内后台修改汇率”的组合，判部分；
- 组合包下单品价格分摊与舍入尾差完全缺失，判遗漏。

### 7.2 下单过程

人工逐项复核结果为23项完整、43项部分、62项纯遗漏、22项错误覆盖，加权有效覆盖下限29.7%。主要缺口如下：

- 产品列表、购物车和结算页停留期间汇率不更新，刷新、前进或返回后才更新的会话边界不完整；
- 硬件、服务、组合包的单价、数量、总价未逐字段断言；
- 税、运费、返利、现金折扣、节省金额、应付总额被合并成“金额正确”；
- 确认页币种、汇率和免责声明的锁定时点不正确；
- 修改数量、服务年限、增删商品和返利后，各金额联动验证不足；
- 历史订单不得被后台新汇率、免责声明和配置状态污染的检查不完整。

### 7.3 Search Order

- Re-order五类分支没有展开：MYR原汇率、MYR新汇率、停用后转USD、USD保持USD、启用后转MYR；
- All、Pending、Closed页签间功能一致性不足；
- 订单金额、实际支付金额、锁定汇率、币种等业务字段缺少独立断言；
- 订单导出字段、筛选范围和历史/非MYR数据兼容覆盖不足。

### 7.4 PC订单审批

- 移动端和后台待办没有分别展开；
- 受控、法务、销售审批没有形成角色矩阵；
- 单价、订单金额、实际支付金额、返利、现金折扣、币种和2位精度被综合描述压缩；
- 历史订单和非MYR订单保持原状的断言不足。

### 7.5 测试工程化质量

- 多数平台点缺前置条件、测试数据、步骤、计算值、独立断言和Requirement ID；
- 171条范围内测试点仍包含功能层、T1/T2/T3的语义重复，条数不等于独立覆盖；
- 使用具体账号、数据库字段、状态枚举和缓存策略，环境耦合较强；
- 一个综合平台点可能映射多个人工点，缺陷定位和执行结果无法细分；
- required coverage与exploratory tests没有分开统计。

## 8. 平台优化建议

### P0：正确性与覆盖可证明

1. 需求进入生成器后先原子化，生成唯一`Requirement ID`。
2. 建立`PRD/确认结论 > 设计/API > 代码现状 > 模型推断`的来源优先级。
3. 发现PRD与代码冲突时输出“待确认问题”，禁止生成确定性预期。
4. 输出`Requirement ID ↔ Case ID ↔ Assertion ID`双向追踪矩阵。
5. 自动检测默认值、是否可编辑、肯定/否定、精度、锁定时点和越界行为冲突。

### P1：颗粒度和业务状态能力

1. 一个测试点只验证一个规则；单条映射超过5个需求点时必须展开独立断言。
2. 建立“页面 × 金额字段”“角色 × 订单状态”“配置状态 × 订单生命周期”“汇率变化时点 × 页面行为”矩阵。
3. 金额测试必须生成USD原值、汇率、计算公式、舍入方式和明确MYR期望值。
4. 使用订单状态机生成产品列表、购物车、结算、确认、成功、详情和审批的快照传递测试。
5. Re-order、历史订单和配置启停必须按决策表生成，而不是一句综合描述。

### P2：平台工程能力

1. 将账号、国家、币种、汇率和环境信息参数化。
2. 功能层与T1/T2/T3引用同一Case ID，避免重复计数。
3. 生成后自动输出遗漏、弱预期、冲突、需求外推断和语义重复清单。
4. 支持需求变更后的影响分析和增量生成。
5. 分开统计需求覆盖测试与探索性扩展测试。

## 9. 管理建议与验收门槛

平台当前评级仍建议为：**C级——需整改**。

即使剔除UI和CES，仍触发以下不通过门禁：

- 存在P0规则冲突；
- 机器高相似候选率只有26.3%，且人工抽查仍有明显假阳性；
- 137项有效人工检查点无候选；
- 极端场景和订单审批覆盖不足；
- 没有需求与测试点双向追踪。

建议平台整改验收指标：

| 指标 | 门槛 |
|---|---:|
| P0需求完整覆盖率 | 100% |
| 总体严格有效覆盖率 | ≥90%，目标≥95% |
| 明确规则错误 | 0 |
| P0遗漏 | 0 |
| 部分覆盖占比 | ≤10% |
| 需求/用例/断言双向追踪率 | 100% |
| “正确/正常/一致”但无量化预期 | ≤3% |
| 无依据规则 | ≤1%，且必须标记待确认 |
| 人工无需修改接受率 | ≥85% |
| 同输入重复生成覆盖波动 | ≤3个百分点 |

## 10. 最终意见

剔除UI和CES后，平台仍能识别主要业务主题：机器高相似召回26.3%、加权候选估算45.0%、主题召回63.7%。但人工抽查证实机器结果含大量跨页面误配，因此这些数字不能当作最终业务覆盖率；真实有效覆盖尚未被可追踪矩阵证明，且现有抽查显示45.0%偏乐观。平台在风险发散方面有价值，在需求忠实度、规则正确性、原子断言、历史快照和测试工程化方面明显不足。

当前产物适合作为人工测试工程师的补充草稿，不适合直接替代正式测试设计或单独承担发布准入。
