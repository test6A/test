# PC 马币下单需求 vs AI 测试点测试评审报告

## 1. 评审结论

本报告将 `PC马币下单项目-测试导图.mm` 视为需求及验收口径，将 `mindmap-ai (1).mm` 视为待评审测试设计。

综合结论：**AI 测试点可作为测试设计初稿，但不能直接进入正式执行。** 它覆盖了币种配置、MYR 下单主流程、汇率同步、告警及部分异常降级，但存在明确需求冲突，且对页面字段、历史订单、再次下单、审批/CES、导出及极端场景覆盖不足。

> **需求内容覆盖率：64.0%（304 / 475）**  
> **明确遗漏或未形成有效对应：171 项**

覆盖率采用跨模块内容匹配，不按模块名称、层级或双方测试点数量计算。一个 AI 测试点可以覆盖多个需求检查点；与需求口径相反的测试点即使主题相同，也应视为错误，执行前必须修正。

### 模块覆盖概览

| 需求域 | 内容覆盖 | 主要评价 |
|---|---:|---|
| 预购订单完整链路 | 100.0% | 有主链路，但各审批节点断言仍偏粗 |
| 渠道订单完整链路 | 100.0% | 有主链路，缺少逐角色、逐状态数据校验 |
| 极端场景 | 25.0% | 汇率空值、跨页切币、组合包分摊等不足 |
| PC / 多币种国家配置 | 83.1% | 主题较全，但字段口径错误和 UI 细节遗漏较多 |
| PC / 下单过程 | 55.1% | 主流程具备，页面级金额字段与锁定规则不完整 |

## 2. 明确错误点 / 与需求冲突点

以下问题不是普通遗漏，而是测试预期与需求相反。若按 AI 测试点执行，可能把正确实现判为缺陷，或把错误实现判为通过。

| 优先级 | 位置 | 需求口径 | AI 测试点口径 | 判断与处理 |
|---|---|---|---|---|
| P0 | Admin / 新增配置 / 免责声明 | 需要中文、英文免责声明字段，必填；前台横幅展示配置文案 | “Admin 不含免责声明字段，前台仅展示汇率和生效日期” | **直接冲突**。删除原预期，补充中英文必填、编辑回显、语言切换、历史订单快照测试 |
| P0 | Admin / 编辑配置 / 国家 | 编辑弹窗国家按需求只读或沿用新增值，不应随意改变配置主体 | “编辑时国家字段可重新选择并保存成功” | **直接冲突**。改为国家字段置灰只读，并补接口篡改拦截 |
| P0 | 金额精度默认值 | 配置输入框默认值为 2，允许范围 0～4 | “默认 4” | **数值口径错误**。统一为默认 2，并保留 0、4 合法边界测试 |
| P0 | 前台金额舍入 | 需求多处明确：不论后台配置精度，前台价格四舍五入保留 2 位 | “按配置精度展示，ROUND_HALF_UP；默认精度 4” | **显示规则相反**。应分别验证配置存储精度与前台展示 2 位，不可混为一条 |
| P0 | 确认页币种 | 确认页继承上一页面选中币种并置灰，不可编辑；汇率锁定 | “确认页切换币种仅切换展示” | **交互规则冲突**。确认页应验证只读、刷新不变、返回上一页后重新进入才更新 |
| P1 | Admin / 汇率数据源 | UI 默认显示“财务月度基准汇率”，其他暂未开放项可见但不可选 | “仅 DW_GL_CORPORATE 可选，其余为空/disabled” | 可能把后台枚举值当作 UI 文案。应分别验证显示名称、枚举值和禁用项，不应只断言技术代码 |
| P1 | 产品列表 / 默认币种 | 需求强调 Malaysia 启用时默认 MYR，并按页面流转规则更新/锁定 | “再次访问沿用上次选择” | 需求未定义持久记忆。属于未经确认的产品规则，先标记待澄清，不应作为通过条件 |
| P1 | 导出免责声明 | 需求定义具体导出字段及币种，不含“必须增加参考金额免责声明”的明确口径 | AI 自行增加导出免责声明 | 属于需求外推断。可作为建议，但不能当作既定验收标准 |

## 3. 主要遗漏点

### 3.1 P0：核心链路和资金口径

1. **CES 分阶段校验严重不足**

   - CES / 商务-待确认下单合同：审批页、已办页的币种与金额字段。
   - CES / 商务-已确认下单合同：确认前后币种、金额和状态一致性。
   - CES / 订单员-待审批下单合同：待审批展示和上游订单快照一致性。
   - CES / 订单员-审批过的下单合同：审批后币种、金额、状态及历史值。
   - CES / 导出 PO：Unit Price、Total Amount、Sub total、返利、现金折扣、Freight、TOTAL AMOUNT、币种等字段。
   - CES 抛单失败、重试、重复消息、字段缺失、optional 字段兼容也未形成完整闭环。

2. **各页面金额字段矩阵不完整**

   需求要求在产品列表、购物车、结算页、确认页、成功页、订单详情、合同详情、审批页逐项验证：

   - 硬件、服务、组合包的单价、数量、总价。
   - 小计、税、运费、返利、现金折扣、节省金额、应付总额。
   - USD/MYR 符号、换算结果和统一保留 2 位。
   - 切换币种、修改数量、修改服务年限、增删产品后的联动更新。
   - 组合包下单品的价格展示和价格分摊。

   AI 测试点多用“一组金额正确”概括，缺少逐字段断言，容易出现某一个金额字段错而整条用例仍被判通过。

3. **汇率锁定时点和历史快照验证不完整**

   - 产品列表、购物车、结算页：停留当前页时是否保持旧汇率；刷新、前进、返回时何时获取新汇率。
   - 确认页：继承上一页汇率并锁定，刷新不变。
   - 成功页、详情页、合同页、审批页、CES：始终使用订单确认时快照。
   - 后台修改汇率、免责声明或停用配置后，历史订单不得被新配置污染。
   - 7 天内修改生效汇率后，渠道确认订单仍使用销售下单时历史汇率。

### 3.2 P1：高频功能与回归风险

1. **Search Order / 再次下单遗漏**

   - MYR 原订单、汇率未变化：再次下单默认 MYR，按规定选择原汇率或当前规则。
   - MYR 原订单、汇率已变化：再次下单默认 MYR，并使用最新汇率。
   - 后台停用币种配置：再次下单默认 USD。
   - USD 原订单：配置未启用时默认 USD；启用/新增配置后再次下单默认 MYR。
   - All、Pending、Closed 页签的展示、办理和再次下单行为一致性。

2. **订单/合同详情及导出字段遗漏**

   - 锁定利率列、币种列、订单金额、实际支付金额。
   - Order Amount、Actual Payable Amount、Unit Price。
   - PO 中 Sub total、Deducted Rebate Amount、Cash discount、Freight、TOTAL AMOUNT。
   - 历史数据及非 MYR 订单保持原状；没有 MYR 数据时页面不应出现无意义变更。

3. **审批页面覆盖不足**

   - 移动端审批和后台待办需分别覆盖受控、法务、销售审批。
   - 产品列表：单价、订单金额、实际支付金额及 Total。
   - 付款模块：订单金额、实付金额、返利、现金返点/现金折扣、币种只读。
   - 历史/非 MYR 单据保持原状。

4. **Admin UI 和交互细节遗漏**

   - 新增/编辑弹窗标题、模块结构、保存/取消/X 按钮及关闭行为。
   - 国家搜索的模糊/精确查询、大小写、单选、清空、高亮和联动国家编码。
   - 展示币种切换、清空及符号联动。
   - 波动阈值、缓冲天数、精度的键盘输入、粘贴、非数字、步进按钮和边界。
   - 保存防连点、必填项标红、失败后不关闭弹窗、取消后不保存。
   - 创建/修改时间格式与更新逻辑。
   - 分页 9/10/11 条边界、首页/尾页按钮、页码省略、每页条数切换。

### 3.3 P2：极端、兼容和质量属性

- 后台马币汇率为空时，Malaysia 仍应可用 USD 正常下单。
- 产品列表加载 MYR 后进入购物车并来回切币，所有价格和符号保持一致。
- 组合包下单品的价格分摊与舍入尾差。
- 汇率极大/极小、零、负数、超长小数、逆向汇率精度和累计误差。
- 并发修改配置、下单提交瞬间汇率切换、重复提交、网络超时和幂等。
- 多标签页、浏览器刷新、前进后退、会话过期、权限变化后的状态一致性。
- Chrome/Edge、不同分辨率、长文案、英文文案和金额列溢出。

## 4. AI 测试点中的有价值扩展

以下内容虽然不一定在需求导图中明确展开，但有测试价值，建议保留为“需求待确认/增强测试”，不要直接当作既定需求：

- 接口级权限拦截，防止只隐藏按钮但接口可越权。
- 同一国家重复新增的唯一性约束。
- 汇率同步空值、0、负数、非数字过滤及失败告警。
- 缓存/数据库不可用时的降级策略。
- 不同 partnerCode 确认订单的越权拦截。
- 待确认订单状态、产品一致性和重复确认校验。
- 提交失败时“不创建订单、不扣返利、不发审批、不抛 CES”的事务完整性。
- 分享购物车不复用分享时价格和汇率，接收方重新计算。
- 金额筛选和排序按 USD 主金额的稳定口径。
- 浏览器兼容和接口幂等性。

## 5. 期望的测试点优化方式

### 5.1 重构测试点格式

每条用例至少包含：

`编号 / 优先级 / 需求点 / 前置数据 / 用户角色 / 操作步骤 / 明确预期 / 数据库或接口校验 / 是否自动化`

不要使用“金额正确”“展示正常”“流程无异常”作为唯一预期。应展开为：字段名、币种、计算公式、舍入规则、数据来源、锁定时点和状态变化。

### 5.2 建立四个核心测试矩阵

1. **页面 × 金额字段矩阵**：产品列表、购物车、结算、确认、成功、订单详情、合同详情、审批、CES、PO。
2. **角色 × 流程矩阵**：销售、渠道、受控、法务、商务、订单员。
3. **币种配置状态 × 订单生命周期矩阵**：未配置、停用、启用、修改汇率、修改展示币种、删除/失效；新订单、待确认、审批中、已完成、历史订单、再次下单。
4. **汇率时点矩阵**：进入页面前变更、停留页面时变更、刷新后、进入确认页后、提交瞬间、提交后、渠道确认前后、CES 审批前后。

### 5.3 将冲突项设置为评审门禁

在需求负责人确认以下口径前，不应完成测试评审：

- 免责声明字段是否存在、是否必填、哪些页面展示、是否进入订单快照。
- 国家字段编辑时是否只读。
- 配置精度默认值究竟是 2 还是 4；前台是否始终显示 2 位。
- 确认页币种是否允许切换。
- UI 展示“财务月度基准汇率”与后台枚举 `DW_GL_CORPORATE` 的映射。
- 是否记忆用户上次选择的币种。
- 再次下单使用原汇率还是最新汇率的准确规则。

## 6. 执行优先级建议

### 第一批：P0，阻断上线

- 修正全部需求冲突测试点。
- 补齐销售/渠道两条 E2E 主流程和汇率快照断言。
- 补齐确认页、审批、CES 和 PO 的金额/币种校验。
- 补齐历史订单不受后台新配置污染。
- 补齐金额计算、舍入和组合包分摊。

### 第二批：P1，核心回归

- 补齐 Search Order 三个页签、再次下单和导出。
- 补齐 Admin 字段边界、权限、保存、取消、防连点和分页。
- 补齐配置启停及页面刷新/返回的汇率更新规则。

### 第三批：P2，稳定性和体验

- 异常降级、并发、幂等、超时、数据污染恢复。
- 浏览器、长文案、国际化、页面布局和性能。
- 建立接口与 UI 自动化回归集。

## 7. 最终评价

AI 导图的优点是覆盖面较广，并主动补充了接口权限、汇率同步、异常降级和数据一致性场景；问题是部分内容来自实现推断而不是需求，且对需求中的大量细粒度验收点进行了过度合并。

建议将当前 AI 导图定位为 **“功能测试设计 V0.7”**：先修正 P0 冲突，再补齐 171 个未覆盖需求点中的核心字段和流程，之后进行一次需求负责人、开发和测试三方口径评审。完成 P0/P1 补充后，目标内容覆盖率应达到 **90% 以上**，P0 需求应达到 **100%**。

详细逐条匹配证据可结合 `PC马币下单项目-内容级覆盖率对比明细.md` 复核。
