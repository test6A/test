# 马来 PC 多币种下单测试点

## 1. 文档信息

- 测试对象：马来 PC 多币种下单一期
- 需求基线：马来PC多币种下单——完整产品方案说明书 V1.0.html
- 澄清基线：马币下单-PC系统一期需求评审会议记录.docx
- 冲突裁决：两份材料冲突时，以 2026-06-30 需求评审会议的明确结论为准
- 输出层级：测试点（What），不展开操作步骤（How）
- 优先级：P0 为核心下单、金额和资金口径；P1 为重要分支及管理能力；P2 为兼容、界面和低频能力

## 2. 已确认的核心口径

1. USD 始终是 PC 底层计算、返利校验与扣减、审批判断及财务主口径；MYR/RM 是可选下单币种和订单展示快照。
2. 币种能力按销往国家命中后台配置，不按销售账号所属国家判断。
3. 产品列表、购物车、结算编辑阶段使用当前生效汇率；进入确认页时锁定币种、汇率和金额。
4. 确认页不提供币种切换；普通订单最终提交时由后端校验价格和汇率，发生变化则下单失败并返回编辑页重新确认。
5. 销售创建 Pending Submission 时即锁定价格、币种和汇率；渠道确认期间不随实时汇率变化，缓存有效期沿用现状 7 天。
6. 订单创建后，列表、详情和审批使用订单快照，不使用当前汇率重算。
7. 返利模块本身不做多币种改造；结算页返利相关金额可展示 MYR，但余额、30% 限制、选择、冻结、扣减和提交仍按 USD。
8. 移动端审批和后台待办不提供币种切换，只展示订单下单币种及对应金额；飞书审批模板不改，仅调整后端传参。
9. ECP 流程本期不改；取消订单、退换货、ERP 财务汇率、合同/发票/收款币种改造不在本期范围。
10. 金额换算使用 USD 金额乘当前或锁定汇率；汇率建议保留 6 位，前台金额按配置展示，马来默认 2 位。
11. 会议约 01:17 后讨论的“签约返利档位调整”是另一项独立需求，不纳入本测试点范围。

## 3. 待确认项与当前测试假设

| 编号 | 待确认项 | 当前测试假设/处理 |
|---|---|---|
| Q-001 | 多币种配置最终放在 PC Admin 还是协同平台，以及沿用哪套菜单权限 | 不验证新增权限模型；仅验证最终落地平台的既有登录、菜单和数据权限不被绕过 |
| Q-002 | 缓冲天数范围：方案写 1～30 天，会议明确允许配置 0 实时生效 | 以会议为准，按 0～30 天设计测试 |
| Q-003 | PENDING 期间连续收到多条新汇率时，是覆盖并重置缓冲期，还是存在其他队列策略 | 暂按方案中的“最新值覆盖并重置；回落到阈值内则取消待生效”验证，开发前需产品确认 |
| Q-004 | CES 保存/回传 USD、MYR 和汇率的最终字段方案，以及尾差责任边界 | 仅把“订单详情可追溯到下单时 USD、MYR 和锁定汇率”作为验收目标；接口字段和换算方待技术方案确定 |
| Q-005 | 订单列表币种切换是仅当前分页出现可切换订单时显示，还是按全部查询结果显示 | 以会议为准，当前页返回含可切换快照数据时显示 |
| Q-006 | 分享购物车是否完整纳入一期、服务项是否随分享传递 | 核心验证导入购物车后按接收方上下文重新算价；分享明细和服务项按最终范围补充 |
| Q-007 | MYR 金额的具体舍入模式（四舍五入、截断或其他）及行金额与总额尾差处理 | 验证全链路使用同一公共规则且结果可追溯；精确算法需产品/财务确认 |
| Q-008 | AI 导入金额币种识别是否属于一期正式范围 | 标记为 P2 候选项，不作为核心上线阻断项，除非排期确认纳入 |
